= Appendix: MCP Gateway

include::partial$console-access.adoc[]

Instead of connecting OpenShift Lightspeed to each MCP server individually, you can route all MCP tool calls through a single, centrally managed gateway endpoint. The gateway aggregates every registered MCP server behind one URL, so platform teams can apply consistent authentication, authorization, and policy enforcement to every tool call. From the perspective of OpenShift Lightspeed, the gateway is just a single MCP server.

This appendix deploys the full stack behind the gateway: Red Hat OpenShift AI, Connectivity Link with its MCP Gateway, the MCP Lifecycle operator, and the MCP server for Red Hat OpenShift. All the work happens in the *Bastion* tab.

[#install-rhoai]
== 1. Install Red Hat OpenShift AI

The MCP Lifecycle operator is a Red Hat OpenShift AI component, so OpenShift AI must be installed first:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: redhat-ods-operator
---
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: rhods-operator
  namespace: redhat-ods-operator
spec: {}
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: rhods-operator
  namespace: redhat-ods-operator
spec:
  channel: stable-3.x
  installPlanApproval: Automatic
  name: rhods-operator
  source: redhat-operators-snapshot-lightspeed
  sourceNamespace: openshift-marketplace
  startingCSV: rhods-operator.3.5.0
EOF
----

Wait for the operator installation to complete:

[source,bash,role="execute"]
----
oc wait csv -n redhat-ods-operator -l operators.coreos.com/rhods-operator.redhat-ods-operator="" --for=jsonpath='{.status.phase}'=Succeeded --timeout=900s
----

Create the `default-dsc` DataScienceCluster with only the components this appendix needs: the dashboard (which hosts the MCP catalog) and the MCP Lifecycle operator. Every other component is explicitly removed to keep the footprint minimal:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: datasciencecluster.opendatahub.io/v2
kind: DataScienceCluster
metadata:
  name: default-dsc
spec:
  components:
    dashboard:
      managementState: Managed
    mcplifecycleoperator:
      managementState: Managed
    workbenches:
      managementState: Removed
    aipipelines:
      managementState: Removed
    kserve:
      managementState: Removed
    kueue:
      managementState: Removed
    ray:
      managementState: Removed
    trustyai:
      managementState: Removed
    modelregistry:
      managementState: Removed
    trainingoperator:
      managementState: Removed
    feastoperator:
      managementState: Removed
    llamastackoperator:
      managementState: Removed
    ogx:
      managementState: Removed
    mlflowoperator:
      managementState: Removed
    trainer:
      managementState: Removed
    sparkoperator:
      managementState: Removed
    aigateway:
      managementState: Removed
EOF
----

Wait for the DataScienceCluster to become ready:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready datasciencecluster/default-dsc --timeout=1200s
----

Wait for the MCP Lifecycle operator to be running:

[source,bash,role="execute"]
----
oc wait --for=condition=Available deployment -l app.kubernetes.io/name=mcp-lifecycle-operator -n redhat-ods-applications --timeout=600s
----

Finally, turn on the MCP catalog in the OpenShift AI dashboard. This adds the *AI hub* -> *MCP servers* section, where MCP servers can also be deployed and managed from the web console:

[source,bash,role="execute"]
----
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications \
  --type=merge -p '{"spec":{"dashboardConfig":{"mcpCatalog":true}}}'
----

[#install-connectivity-link]
== 2. Install Connectivity Link

Connectivity Link provides the Gateway API infrastructure and the authentication components that the MCP Gateway builds on:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: kuadrant-system
---
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: kuadrant
  namespace: kuadrant-system
spec:
  upgradeStrategy: Default
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: rhcl-operator
  namespace: kuadrant-system
spec:
  channel: stable-1.5
  installPlanApproval: Automatic
  name: rhcl-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  startingCSV: rhcl-operator.v1.5.0
EOF
----

Wait for the operator installation to complete:

[source,bash,role="execute"]
----
oc wait csv -n kuadrant-system -l operators.coreos.com/rhcl-operator.kuadrant-system="" --for=jsonpath='{.status.phase}'=Succeeded --timeout=600s
----

Then create the `Kuadrant` custom resource:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: kuadrant.io/v1beta1
kind: Kuadrant
metadata:
  name: kuadrant
  namespace: kuadrant-system
spec: {}
EOF
----

Wait for the Kuadrant instance to become ready:

[source,bash,role="execute"]
----
oc wait kuadrant/kuadrant --for="condition=Ready=true" -n kuadrant-system --timeout=600s
----

[#deploy-mcp-gateway]
== 3. Deploy the MCP Gateway

With Connectivity Link 1.5, the `Kuadrant` custom resource deploys the MCP Gateway controller automatically: the `mcp-gateway-controller` pod runs in the `kuadrant-system` namespace, and the `mcp.kuadrant.io` custom resource definitions are already in place. No separate operator subscription is needed. Confirm that the controller is running:

[source,bash,role="execute"]
----
oc wait --for=condition=Available deployment/mcp-gateway-controller -n kuadrant-system --timeout=300s
----

Then create the `Gateway` that listens for MCP traffic and the `MCPGatewayExtension` that activates the gateway on it:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: mcp-system
---
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: mcp-gateway
  namespace: mcp-system
spec:
  gatewayClassName: openshift-default
  listeners:
    - name: mcp
      hostname: mcp-gateway-istio.mcp-system.svc.cluster.local
      port: 8080
      protocol: HTTP
      allowedRoutes:
        namespaces:
          from: All
---
apiVersion: mcp.kuadrant.io/v1
kind: MCPGatewayExtension
metadata:
  name: mcp-gateway-ext
  namespace: mcp-system
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: mcp-gateway
    namespace: mcp-system
    sectionName: mcp
  httpRouteManagement: Enabled
EOF
----

Wait for the extension to become ready:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready mcpgatewayextension/mcp-gateway-ext -n mcp-system --timeout=300s
----

Optionally, enable the Connectivity Link console plugin to visualize and manage the gateway from the web console:

[source,bash,role="execute"]
----
oc patch console.operator.openshift.io cluster --type json \
  -p '[{"op":"add","path":"/spec/plugins/-","value":"kuadrant-console-plugin"}]'
----

The console reloads automatically and a *Connectivity Link* section appears in the navigation menu. Its *MCP management* pages list the gateway extensions, the registered MCP servers with their online status, and the attached policies, and the *MCP Inspector* lets you validate and run individual tools directly.

[#deploy-mcp-server]
== 4. Deploy the MCP server for Red Hat OpenShift

Deploy the MCP server for Red Hat OpenShift as an `MCPServer` resource, with its configuration, service account, and read-only RBAC:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: mcp-servers
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: openshift-mcp-server-ro
  namespace: mcp-servers
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: openshift-mcp-server-ro
rules:
  - apiGroups: [""]
    resources: [namespaces, nodes]
    verbs: [get, list]
  - apiGroups: [project.openshift.io]
    resources: [projects]
    verbs: [get, list]
  - apiGroups: [metrics.k8s.io]
    resources: [pods, nodes]
    verbs: [get, list]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: openshift-mcp-server-ro
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: openshift-mcp-server-ro
subjects:
  - kind: ServiceAccount
    name: openshift-mcp-server-ro
    namespace: mcp-servers
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: openshift-mcp-server-ro-view
  namespace: mcp-servers
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: view
subjects:
  - kind: ServiceAccount
    name: openshift-mcp-server-ro
    namespace: mcp-servers
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
data:
  config.toml: |
    port = "8080"
    stateless = true
    read_only = true
    list_output = "table"
    cluster_provider_strategy = "in-cluster"
    cluster_auth_mode = "passthrough"
    require_oauth = false
    skip_jwt_verification = true
    disable_dynamic_client_registration = true
    require_tls = false
    toolsets = ["core", "config"]
    [[denied_resources]]
    group = ""
    version = "v1"
    kind = "Secret"
    [http]
    read_header_timeout = "10s"
    max_body_bytes = 1048576
    rate_limit_rps = 2
    rate_limit_burst = 4
---
apiVersion: mcp.x-k8s.io/v1alpha1
kind: MCPServer
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
spec:
  source:
    type: ContainerImage
    containerImage:
      ref: registry.redhat.io/openshift-mcp-tech-preview/openshift-mcp-server-rhel9@sha256:855466299c3178f7d9f96a1511005ca6161b8cc6b294df9907c234ce8ecfd0f2
  config:
    port: 8080
    path: /mcp
    arguments: ["--config", "/etc/mcp-config/config.toml"]
    storage:
      - path: /etc/mcp-config
        permissions: ReadOnly
        source:
          type: ConfigMap
          configMap:
            name: openshift-mcp-server
      - path: /tmp
        permissions: ReadWrite
        source:
          type: EmptyDir
          emptyDir:
            sizeLimit: 64Mi
  runtime:
    replicas: 1
    resources:
      requests: {cpu: 100m, memory: 128Mi}
      limits: {cpu: 500m, memory: 512Mi}
    security:
      serviceAccountName: openshift-mcp-server-ro
      podSecurityContext:
        runAsNonRoot: true
        seccompProfile: {type: RuntimeDefault}
      securityContext:
        runAsNonRoot: true
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities: {drop: [ALL]}
    health:
      readinessProbe:
        httpGet: {scheme: HTTP, path: /healthz, port: 8080}
        periodSeconds: 10
        timeoutSeconds: 3
      livenessProbe:
        httpGet: {scheme: HTTP, path: /healthz, port: 8080}
        initialDelaySeconds: 15
        periodSeconds: 20
        timeoutSeconds: 3
  mcp:
    stateless: true
EOF
----

Wait for the MCP server to be ready:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready mcpserver/openshift-mcp-server -n mcp-servers --timeout=600s
----

[#register-mcp-server]
== 5. Register the MCP server

Expose the MCP server to the gateway with an `HTTPRoute` labeled for discovery, then register it with an `MCPServerRegistration`:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
  labels:
    mcp-server: 'true'
spec:
  hostnames:
    - mcp-gateway-istio.mcp-system.svc.cluster.local
  parentRefs:
    - name: mcp-gateway
      namespace: mcp-system
      sectionName: mcp
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /
      backendRefs:
        - name: openshift-mcp-server
          port: 8080
---
apiVersion: mcp.kuadrant.io/v1
kind: MCPServerRegistration
metadata:
  name: openshift-mcp-server
  namespace: mcp-servers
spec:
  prefix: openshift_
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: openshift-mcp-server
    namespace: mcp-servers
EOF
----

Wait for the registration to discover the server's tools:

[source,bash,role="execute"]
----
oc wait --for=condition=Ready mcpsr/openshift-mcp-server -n mcp-servers --timeout=300s
oc get mcpsr -n mcp-servers
----

[#configure-ols]
== 6. Point OpenShift Lightspeed at the gateway

Finally, reconfigure the `OLSConfig` to route MCP tool calls through the gateway. The gateway is reachable in-cluster at the listener hostname, exposes its Streamable HTTP endpoint at the `/mcp` path, and the `Authorization` header forwards the logged-in user's bearer token so the gateway can authorize each request:

[source,bash,role="execute"]
----
oc patch olsconfig cluster --type merge -p '{"spec":{"featureGates":["MCPServer"],"mcpServers":[{"name":"mcp-gateway","url":"http://mcp-gateway-istio.mcp-system.svc.cluster.local:8080/mcp","timeout":30,"headers":[{"name":"Authorization","valueFrom":{"type":"kubernetes"}}]}]}}'
----

NOTE: The patch replaces the whole _mcpServers_ list, so any MCP server registered directly (as in the custom MCP servers module) is superseded by the gateway. Register those servers behind the gateway instead.

The OpenShift Lightspeed app server pod redeploys with the new configuration. Once it is running, the intelligent assistant discovers the tools of every MCP server registered behind the gateway, prefixed with the registration prefix. Ask a question that requires cluster introspection and the tool calls now route through the gateway.
