OpenShift Lightspeed is an agent for the Red Hat OpenShift Container Platform. It helps users with general OpenShift and Red Hat product knowledge, lifecycle management of cluster resources, troubleshooting, root cause analysis, remediation, observability, and more. Powered by large language models (LLMs) and retrieval-augmented generation (RAG), OpenShift Lightspeed makes OpenShift more accessible to users and helps increase user productivity.

OpenShift Lightspeed presents two complementary capabilities:

* *OpenShift Lightspeed intelligent assistant*: a conversational AI chatbot that OpenShift users can use to understand concepts, get configuration guidance, generate YAML, create, monitor and manage workloads running in the cluster and troubleshoot issues through natural language chat.
* *OpenShift Lightspeed autonomous agents*: an autonomous layer on your cluster that can investigate problems, propose remediation plans, apply approved fixes, and verify outcomes. All driven by plain-language descriptions, cluster update paths or firing alerts, without step-by-step guidance from the user.

NOTE: OpenShift Lightspeed autonomous agents is a Technology Preview feature introduced in OpenShift Lightspeed 2.0 that requires OpenShift Container Platform 5.0 and later. The intelligent assistant supports OpenShift Container Platform 4.16 and later.

OpenShift Lightspeed today is a relatively small and lightweight system that you deploy into each OpenShift Container Platform cluster. The operator deploys the following core components:

* Two web console plugins (the chat interface and the agentic runs dashboard)
* A back-end application server (processes questions, calls the LLM, runs tool loops)
* An agentic back-end (orchestrates the agentic workflows)
* An OpenTelemetry collector (audit logging and tracing for AI-assisted and agentic workflows)
* A PostgreSQL database (for temporary conversation caching)
* A Red Hat Offline Knowledge Portal (RHOKP) component (serves Red Hat product documentation via Solr, used as built-in RAG context)
* An OpenShift MCP server (enables cluster interaction, connecting OpenShift Lightspeed to the OpenShift API and monitoring stack)

== RAG basics

RAG is a way of providing additional context to an LLM to help improve the quality of responses. OpenShift Lightspeed gets this context from the Red Hat Offline Knowledge Portal (RHOKP) component. When relying on only the LLM, two common problems can arise:

1. Hallucination: the model invents an answer that is not grounded in fact, even when the model was trained with the answer
2. Missing data: the model was never trained on the required information in the first place, so answers could be anything

When you provide contextual information to the LLM along with your question, response quality can improve dramatically, even if the model was never trained on the specific contextual information.

RHOKP serves the relevant OpenShift Container Platform documentation matched to the cluster version, and OpenShift Lightspeed uses that content as additional context when answering user questions.
