OpenShift Lightspeed is a virtual assistant for the Red Hat OpenShift Container Platform. It helps users with general OpenShift and Red Hat products knowledge, troubleshooting, root cause analysis, and more. Powered by large language models (LLMs) and retrieval-augmented generation (RAG), OpenShift Lightspeed makes OpenShift more accessible to users and helps increase user productivity.

== OpenShift Lightspeed Architecture

OpenShift Lightspeed today is a relatively small and lightweight system that you deploy into each OpenShift Container Platform cluster. The operator deploys the following core components:

* A web console plugin (the chat interface)
* A back-end application server (processes questions, calls the LLM, runs tool loops)
* A PostgreSQL database (for temporary conversation caching)
* A Red Hat Offline Knowledge Portal (RHOKP) component (serves Red Hat product documentation via Solr, used as built-in RAG context)
* An OpenShift MCP server (enables cluster interaction, connecting OpenShift Lightspeed to the OpenShift API and monitoring stack)

image::ols-arch.png[OpenShift Lightspeed architecture]

You can also see that OpenShift Lightspeed talks to a model provider. In the case of this lab environment, that provider is *Azure OpenAI* using the *GPT-4 model*. There are five supported public model providers:

* OpenAI
* Microsoft Azure OpenAI
* IBM watsonx
* Google Vertex AI (Gemini models, as well as Anthropic Claude models running on Vertex)
* AWS Bedrock

Additionally, if you want to self-manage your LLM, we also support the Red Hat on-premises model provider solutions:

* Red Hat OpenShift AI
* Red Hat Enterprise Linux AI (RHEL AI)

== RAG Basics

RAG is a way of providing additional context to an LLM to help improve the quality of responses. OpenShift Lightspeed gets this context from the Red Hat Offline Knowledge Portal (RHOKP) component. When relying on only the LLM, two common problems can arise:

1. Hallucination - the model invents an answer that is not grounded in fact, even when the model was trained with the answer
2. Missing data - the model was never trained on the required information in the first place, so answers could be anything

When providing contextual information to the LLM at the time of asking a question, the response quality can be dramatically improved, even if the model was never trained on the specific contextual information.

RHOKP serves the relevant OpenShift Container Platform documentation matched to the cluster version, and OpenShift Lightspeed uses that content as additional context when answering user questions.

The specific details of vector databases and embedding and encoding are outside the scope of this lab.
