= Simplify VM management with OpenShift Lightspeed

include::partial$console-access.adoc[]

Virtual machines in OpenShift are managed as custom resources, which means the intelligent assistant can help you understand, configure, and troubleshoot them just like any other OpenShift resource.

This lab environment comes with OpenShift Virtualization already deployed and configured. You can start working with virtual machines right away. In this module, you'll explore how the assistant assists with virtualization workloads across different user scenarios, from newcomers learning the basics to experienced admins migrating from other platforms.

image::arch-module08.svg[Architecture with the built-in MCP server highlighted, align="center", link=self, window=blank]

In this module you work with the highlighted pieces: the core OpenShift Lightspeed components plus the built-in MCP server to ask about Virtualization resources.

[#new-virtualization-users]
== New virtualization users

If you're new to OpenShift Virtualization, there's a lot to learn. The chatbot can help you understand the key concepts and resources you'll be working with.

For example, two important concepts when it comes to creating your first virtual machine in OpenShift Virtualization are InstanceTypes and VM Templates.

Open the chat interface, click the *Clear chat* (trash can) button, and make sure *Ask mode* is selected. Then ask it to explain the difference between both resources:

[source,role="copypaste"]
----
What's the difference between a VM InstanceType and a VM Template?
----

The assistant will provide a clear explanation of both concepts and when it makes sense to use one or the other.

This kind of conceptual guidance helps you quickly understand the building blocks of OpenShift Virtualization and provides direct links to the relevant documentation sections if you want to dive deeper.

Now that the difference is clear, a new Virtualization user can decide which approach to take. For example, let's ask for the procedure to create a virtual machine from a template:

[source,role="copypaste"]
----
How do I create a Fedora VM from a template?
----

The assistant provides the guidance needed to navigate the cluster in order to create the virtual machine. The initial learning curve is much gentler thanks to the assistance it provides.

[#users-coming-from-different-platforms]
== Users coming from a different platform

If you're migrating to OpenShift Virtualization from another platform like VMware, you might be familiar with different terminology. The good news is that the assistant understands this and can help you translate concepts between platforms.

Let's try an example. If you come from a VMware background, you're probably familiar with vMotion, VMware's technology for live migrating VMs between hosts. Let's ask the chatbot about this:

[source,role="copypaste"]
----
How do I vMotion a VM in OpenShift Virtualization?
----

The assistant understands that you're asking about live migration using VMware terminology. It will explain that the OpenShift Virtualization equivalent is called *Live Migration*, and will likely explain how to proceed in OpenShift Virtualization.

This capability is incredibly valuable because it allows you to keep using the terminology you're already familiar with and learn the OpenShift Virtualization equivalents naturally over time by getting answers that bridge your existing knowledge with new concepts.

[#troubleshooting-virtual-machines]
== Troubleshooting virtual machines

Just like with containerized workloads, things can go wrong with virtual machines. Let's combine what we've learned about cluster interaction and resource attachments to troubleshoot a VM issue.

First, let's use cluster interaction to check if there are any VMs having problems. *Clear chat* and ask:

[source,role="copypaste"]
----
Which virtual machines in the cluster are not in a Running state?
----

The assistant will use cluster interaction tools to query the VirtualMachine resources across your cluster. You should see that there's a RHEL 9 VM in an _ImagePullBackOff_ state that's failing to start.

Now let's dig deeper into what's wrong with this VM. In the OpenShift console, navigate to *Virtualization* -> *VirtualMachines*. Select the *RHEL 9 VM* called `rhel9-demo` to open its details page.

Now, return to the OpenShift Lightspeed chat interface. Then click the *Plus (+)* button to attach information. Go ahead and attach the *Full YAML file* for this VM.

image::broken-vm.png[Broken virtual machine, align="center", link=self, window=blank]

Then you can ask:

[source,role="copypaste"]
----
Why is this VM not starting?
----

The chatbot will analyze the attached YAML and identify the problem: the container image _quay.io/containerdisks/rhel:9-latest_ cannot be pulled because access to the resource is unauthorized.

The response will likely explain why the container image can't be pulled and offer suggestions for fixing it.

This demonstrates how the assistant can troubleshoot virtual machine issues using the same attachment techniques you learned for containerized workloads. Whether you're dealing with pods or VMs, the troubleshooting workflow is consistent and intuitive.
