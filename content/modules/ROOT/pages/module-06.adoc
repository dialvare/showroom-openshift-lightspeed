= Perses Dashboards

The Cluster Observability Operator (COO) is already deployed in this lab environment with Perses. Perses is an open-source, Kubernetes-native dashboard framework designed for observability, and it is integrated directly into the OpenShift web console under the Observe menu.

In this module you will use OpenShift Lightspeed to explore cluster metrics, generate PromQL queries, and produce ready-to-import Perses charts — all from the chat interface.

image::arch-module06.svg[Architecture with the monitoring stack and Perses highlighted]

The highlighted pieces are: the _metrics_ toolset of the built-in MCP server (querying Thanos and Alertmanager), and the Perses dashboard engine deployed by COO.

[#in-line-visualization]
== In-line visualization in OLS

Querying cluster metrics directly requires familiarity with PromQL, the Prometheus query language, which can be complex and time-consuming to master. Instead of writing queries manually, you can simply ask OpenShift Lightspeed in plain language — it will generate the appropriate PromQL query, run it against the cluster, and even render the results as an inline visualization directly inside the chat interface.

Open the OLS chat interface, *clear* any previous conversation, and still in *Troubleshooting mode*, ask:

[source,role="execute",subs=attributes+]
----
What are the top 5 namespaces by CPU usage in this cluster right now? Use PromQL and visualize it
----

OpenShift Lightspeed will invoke the _metrics_ toolset among other tools to run a PromQL query against the in-cluster Thanos Querier and return a ranked list of the five busiest namespaces. Additionally, OpenShift Lightspeed will produce an inline chart from the same query results, giving you a quick visual overview without leaving the chat interface. If everything works as expected you should see a graph similar to this: 

image::ols-graph.png[OpenShift Lightspeed shows rendered graphs]

Let's ask a follow-up question (don't clear the current conversation): 

[source,role="execute",subs=attributes+]
----
Now visualize memory usage over time for those same namespaces as a chart
----

OpenShift Lightspeed will generate another time series diagram to show the memory usage. 

[#import-into-perses]
== Import into Perses

Conversations in OpenShift Lightspeed are transient — once you clear the chat, everything disappears, including any inline charts you generated. For quick, one-off questions that work fine, but in longer troubleshooting sessions you often need to retain that information: revisit it later, track how metrics evolve over time, and complement it with new panels as the investigation deepens. This is where Perses Dashboards come into play, giving you a persistent, shareable view of the metrics you care about.

First, open the Perses UI inside the OpenShift web console. In the left-hand navigation bar go to *Observe* -> *Dashboards (Perses)*. You will see a blue *Create* button in the upper-right corner. Give the dashboard a name such as `OLS Cluster Health`, and select a project, such as `default`. Then press *Create*.

NOTE: The project you select here is just a home for the dashboard object itself — it does not limit the metrics you can see. This lab environment pre-deploys a _GlobalDatasource_ custom resource that makes cluster metrics available to Perses across all namespaces.

You now have an empty dashboard ready to receive panels. Keep this tab open — you will need it alongside the OLS chat interface in the next step.

Now, if you minimized your OpenShift Lightspeed chat interface, open it again. Scroll through your current conversation and hover over one of the graphs. You will see an *Add to Dashboard* icon appear in the upper right corner of the chart:

image::add-perses.png[OpenShift Lightspeed allows to import graphs into Perses]

Click the *Add to Dashboard* icon to instantly import the chart to the Perses dashboard. Do the same with the other graph you created.

Your metrics are now persistently stored in a Perses dashboard that will survive across chat sessions and cluster restarts. From here, Perses gives you full control to tailor the dashboard to your needs: resize and reposition panels, switch between graph types such as time series, stat, or gauge, adjust the time range, customize labels and legends, and much more — all without writing a single line of PromQL or JSON by hand.

== What's Next?

You have just used OpenShift Lightspeed to move from a natural-language question to a live observability dashboard — without manually writing a single PromQL query. This same pattern applies to any team that wants to quickly instrument new services, onboard to metrics, or share a curated view of cluster health with stakeholders.

In the next module, you will extend OpenShift Lightspeed even further by integrating custom MCP servers — connecting it to external systems beyond the cluster itself and giving the model access to tools that no built-in toolset provides.
