= Bring your custom MCP servers into OpenShift Lightspeed

include::partial$console-access.adoc[]

You have already seen OpenShift Lightspeed's built-in MCP server query your cluster's resources and monitoring stack. OpenShift Lightspeed can be extended even further by integrating custom MCP servers that connect to external systems beyond the cluster itself. This feature allows you to register additional MCP servers that provide new tools to the OpenShift Lightspeed instance, enabling the LLM to use those external tools when generating answers to your questions.

image::arch-module07.svg[Architecture with custom MCP servers highlighted, align="center", link=self, window=blank]

In this module you work with the highlighted pieces: a custom MCP server you deploy and register with OpenShift Lightspeed. Note how it sits alongside the built-in one.

[#deploy-the-insights-result-mcp-server]
== Deploy the Insights Result MCP server

You'll deploy the Insights Result MCP server that connects to Red Hat Insights and provides two tools: _get_last_result_for_cluster_ (returns a dictionary with the cluster result) and _get_upgrade_risk_prediction_for_cluster_ (returns a dictionary with the upgrade risks prediction for the given cluster).

OpenShift Lightspeed can connect to MCP servers running outside the cluster, but in this case, the Insights Result MCP server will be deployed directly within your OpenShift cluster.

The whole deployment happens in the *Bastion* tab, applying resources with `oc`. Start by creating the `Project`:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: project.openshift.io/v1
kind: Project
metadata:
  labels:
    kubernetes.io/metadata.name: insights-results-mcp
  name: insights-results-mcp
EOF
----

=== Create the secret

The MCP server authenticates against console.redhat.com with a token from your cluster's pull secret. Create the `Secret` with it:

[source,bash,role="execute"]
----
oc create -n insights-results-mcp secret generic insights-results-secret \
  --from-literal=CONSOLE_REDHAT_PULL_SECRET="$(oc get secrets pull-secret -n openshift-config -o json | jq -r '.data.".dockerconfigjson"' | base64 -d | jq -r '.auths."cloud.openshift.com".auth')"
----

=== Create the ConfigMap

Similarly, create the `ConfigMap` that includes your cluster's ID:

[source,bash,role="execute"]
----
oc create -n insights-results-mcp configmap cluster-info \
  --from-literal=CLUSTER_ID="$(oc get clusterversion -o jsonpath='{.items[].spec.clusterID}')"
----

=== Deploy the server

Now apply the `Deployment`:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    name: insights-results-mcp
  name: insights-results-mcp-server
  namespace: insights-results-mcp
spec:
  replicas: 1
  selector:
    matchLabels:
      app: insights-results-mcp-server
  template:
    metadata:
      labels:
        app: insights-results-mcp-server
    spec:
      containers:
      - env:
        - name: TRANSPORT
          value: streamable-http
        - name: CLUSTER_ID
          valueFrom:
            configMapKeyRef:
              name: cluster-info
              key: CLUSTER_ID
        - name: CLIENT_SECRET
          valueFrom:
            secretKeyRef:
              name: insights-results-secret
              key: CONSOLE_REDHAT_PULL_SECRET
        image: quay.io/joseluis/insights-results-mcp:latest
        imagePullPolicy: Always
        name: container
        ports:
        - containerPort: 5000
          protocol: TCP
          name: mcp
        resources: {}
        terminationMessagePath: /dev/termination-log
        terminationMessagePolicy: File
      dnsPolicy: ClusterFirst
      restartPolicy: Always
      schedulerName: default-scheduler
      securityContext: {}
      terminationGracePeriodSeconds: 30
EOF
----

And the `Service` that exposes the MCP server inside the cluster:

[source,bash,role="execute"]
----
oc apply -f - <<'EOF'
apiVersion: v1
kind: Service
metadata:
  labels:
    app.kubernetes.io/name: insights-results-mcp
  name: insights-results-mcp-server
  namespace: insights-results-mcp
spec:
  internalTrafficPolicy: Cluster
  ipFamilies:
  - IPv4
  ipFamilyPolicy: SingleStack
  ports:
  - name: mcp
    port: 5000
    protocol: TCP
    targetPort: mcp
  selector:
    app: insights-results-mcp-server
  sessionAffinity: None
  type: ClusterIP
EOF
----

Wait for the server to roll out:

[source,bash,role="execute"]
----
oc rollout status deployment/insights-results-mcp-server -n insights-results-mcp
----

The Insights Result MCP server is now configured and running in your cluster. It's time to connect it to your OpenShift Lightspeed instance.

[#configure-openshift-lightspeed]
== Configure OpenShift Lightspeed

As you have seen in previous modules, the configuration for the OpenShift Lightspeed Operator is done in the `OLSConfig` resource.

Navigate to *Ecosystem* -> *Installed Operators* -> *OpenShift Lightspeed Operator* -> *OLSConfig* -> `cluster` -> *YAML*. Once in the YAML editor, add the following lines and click *Save*:

----
...
spec:
...
  llm:
...
  featureGates:
    - MCPServer
  mcpServers:
    - name: insights-results-mcp
      timeout: 5
      url: 'http://insights-results-mcp-server.insights-results-mcp.svc.cluster.local:5000/api/insights-results-mcp/'
----

This new configuration will re-deploy the OpenShift Lightspeed app server pod. Please wait a minute before starting to interact with the intelligent assistant.

NOTE: The Insights Result MCP server used in this lab does not require authentication from OpenShift Lightspeed, but the _mcpServers_ configuration also supports sending custom HTTP headers to servers that do. Header values can come from a _Secret_, from the logged-in user's own Kubernetes token, or from the connecting client. This means you can integrate MCP servers that enforce their own authentication and authorization.

[#use-your-custom-mcp-server]
== Use your custom MCP server

Before asking, if you are not in *Ask mode*, select it from the mode selector. *Clear chat* and now try asking the assistant the following question. The model should use one of the tools that the new MCP server provides:

[source,role="copypaste"]
----
Does Red Hat Insights report any issues or recommendations for this cluster?
----

It's likely that the LLM has decided to use the _get_last_result_for_cluster_ tool provided by the Insights Result MCP server. Click *Approve*. Since the cluster should be healthy, the response will probably indicate that there are no issues listed. This doesn't mean the tool call failed; quite the opposite! The tool successfully retrieved that information from Insights.

[#beyond-containers]
== Beyond containers

So far, you've explored how the intelligent assistant helps with traditional containerized workloads like pods, deployments, routes, and services. But OpenShift is more than just containers. What about virtual machines?

With OpenShift Virtualization, you can run virtual machines alongside your containers on the same OpenShift platform. At the end of the day, virtual machines in OpenShift are just OpenShift custom resources, which means the chatbot can help you with virtual machine workloads too.

Continue to the next module, xref:module-08.adoc[Simplify VM management with OpenShift Lightspeed], to see the assistant in action with virtual machine workloads.
