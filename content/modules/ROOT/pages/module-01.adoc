= OpenShift Lightspeed basics

include::partial$console-access.adoc[]

The OpenShift Lightspeed intelligent assistant uses a natural language interface to allow users to ask questions. You have used many chat interfaces before, so the chatbot should feel very comfortable to use.

The assistant is primarily focused on OpenShift and Red Hat product topics, and will generally decline questions it considers unrelated to those domains. However, if you try hard enough, you can probably get it to do something it wasn't explicitly designed to do, but this is a shortcoming of all non-deterministic language-model-based systems. It is a bit of a game of whack-a-mole trying to keep up with all of the possible negative outcomes, and trying to prevent them is a topic of active research.

NOTE: If you see something bad, be sure to report it using the built-in feedback feature (the thumbs-up/thumbs-down buttons underneath each response, where you can also leave written comments). We will always do our best to improve the quality and safety of the system.

[#starter-question]
== Starter question

This demo is designed to be followed inside this Showroom interface, so everything you need is one click away:

* The *Console* tab opens the OpenShift web console, where most of this lab happens.
* The *Bastion* tab opens a terminal connected to the cluster.
* The view switcher, at the right of the page, lets you display the guide and the console side by side, or focus on either one.

TIP: If you prefer a full browser window, you can also open the web console separately: copy the console link from the *Console Access* section at the top of this module and paste it into a new browser tab. The instructions work the same either way.

Switch to the *Console* tab and log in using the following credentials:

* *Username:* `{openshift_cluster_admin_username}`
* *Password:* `{openshift_cluster_admin_password}`

Once you have logged in, you should see the OpenShift Lightspeed icon in the bottom-right corner of the OpenShift console:

image::ols-icon.png[OpenShift Lightspeed icon, 50%, align="center", link=self, window=blank]

Click the icon, and it will open the chat interface:

image::ols-interface.png[OpenShift Lightspeed chat interface, 60%, align="center", link=self, window=blank]

Why don't you start by asking an easy question like:

[source,role="copypaste"]
----
What are OpenShift Routes?
----

The intelligent assistant should provide a detailed answer about what OpenShift Routes are and their key features. And, if you scroll to the bottom of the response, you will see that it has also provided a link to the documentation that was used to generate its response:

image::related-docs.png[Related documentation, align="center", link=self, window=blank]

This is a great feature because it allows you to go beyond the answer itself and explore the official Red Hat documentation at your own pace. Whether you want to validate the information, dig into advanced configuration options, or simply learn more about the topic, the referenced links give you a direct path to the authoritative source.

[#follow-up-question]
== Follow-up question

The chatbot maintains context from your previous questions within the same chat session, allowing you to ask follow-up questions naturally. This conversational approach makes it easy to dive deeper into topics or move from theory to practice. For example, now that you understand what OpenShift Routes are, you can ask a practical follow-up question like:

[source,role="copypaste"]
----
How do I expose a service using a Route?
----

The assistant remembers your conversation thanks to a PostgreSQL backing store, and provides a more detailed, practical answer based on your previous question. This makes the learning experience more fluid and efficient.

[#yaml-generation]
== YAML generation

Beyond providing explanations and guidance, the intelligent assistant can also generate YAML manifests for you. This is particularly useful when you need to create or modify Kubernetes/OpenShift resources quickly. Building on your previous conversation about Routes, you can ask it to generate actual YAML configuration. Try asking:

[source,role="copypaste"]
----
Show me the YAML configuration for a Route that exposes a service on port 8080 with TLS edge termination
----

The chatbot will provide you with a complete YAML manifest that you can copy and apply to your cluster. The generated YAML follows OpenShift best practices and includes the relevant fields based on your specific requirements. You can then customize this YAML further if needed.

TIP: When you copy a response, the rich-text formatting is preserved, so answers paste cleanly into documents and runbooks. Long code blocks in responses can also be expanded and collapsed to keep the conversation easy to read.

[#query-filters]
== Keeping sensitive data away from the LLM

Everything you type into the chat is ultimately sent to the configured model provider, which for many organizations raises an important question: what about sensitive data? The intelligent assistant includes a redaction layer for exactly this purpose. Administrators can define *query filters*: regular expressions that scrub matching patterns from questions before they leave the cluster.

This lab environment is configured to redact IPv4 addresses. In the OpenShift web console, navigate to *Ecosystem* -> *Installed Operators* in the left-hand menu. Locate the *OpenShift Lightspeed Operator*. Next, click the *OLSConfig* tab, and then click the single OLSConfig instance called `cluster`. Finally, select the *YAML* tab. Find the filter definition under _queryFilters_:

----
...
spec:
...
  ols:
...
    queryFilters:
      - name: ip-address
        pattern: ((25[0-5]|(2[0-4]|1\d|[1-9]|)\d)\.?\b){4}
        replaceWith: <IP-ADDRESS>
----

Let's see it in action. In the chatbot interface, make sure to click the *Clear chat* button (the trash can icon at the top of the chat window). Then ask:

[source,role="copypaste"]
----
My pod at 192.168.4.22 cannot reach the API server. Repeat the exact question I asked, then explain what could be wrong
----

Look closely at the response: when the model repeats your question back, the IP address has been replaced with `<IP-ADDRESS>`. The model never saw the real address; it was redacted before the query left your cluster. You can define as many filters as you need, for example for hostnames, usernames, or internal project names.

[#beyond-the-standard-documentation]
== Beyond the standard documentation

We can keep asking questions about OpenShift resources all day, and the intelligent assistant will provide us with the standard documentation it knows about. But what happens when those procedures are different for your team or organization? For example, at ACME Corp, pod autoscalers are not allowed to be used by default, and there is a special process for enabling autoscaling. Continue to the next module, xref:module-02.adoc[Bring Your Own Knowledge], to learn how you can add your own organizational knowledge, documentation, and policy information to the intelligent assistant.
